# FAQ

## 出力がなぜ日本語なのか？

ソースとなるYamahaのコマンドリファレンスが日本語でのみ公開されているため。このツールは**フォーマット**（HTML→Markdown）を変換するが、コンテンツの翻訳は行わない。日本語テキストはそのまま保持される。

## パラメータテーブルのレイアウトが崩れているのはなぜか？

ソースHTMLの一部テーブルは `rowspan` や `colspan` を使用している。標準的なMarkdownテーブルはセルのスパンをサポートしないため、変換後はスパン情報が失われる。ただしセルのテキスト内容はすべて保持される。

## 何件のファイルが変換されるか？

通常の実行で約**1,237件のコマンドページ**が変換される（ナビゲーションファイルは自動的にスキップ）。正確な件数はアーカイブのバージョンによって異なる。

## 特定のファームウェアバージョンのアーカイブにも使えるか？

使える。任意のバージョンのアーカイブの `html/` ディレクトリを `--input` で指定すれば良い。特定のバージョンを前提とした処理は行っていない。

## `output/` ディレクトリが既に存在する場合は上書きされるか？

される。ファイルは `fs.writeFileSync` で書き込まれ、同じパスに既存ファイルがあれば上書きされる。ディレクトリとその親構造が存在しない場合は自動作成される。

## オフラインで動作するか？

動作する。コンバータはネットワーク通信を一切行わない。npmの依存パッケージをインストールすれば、完全オフライン環境で実行できる。

## なぜApache 2.0でMITではないのか？

Apache 2.0はMITにない明示的な特許付与条項を含み、企業ユーザーにとっての法的リスクを低減する。使用・改変・配布の自由度はMITと同等。

## Yamahaが新しいアーカイブをリリースした際の更新方法は？

新しい `Cmdref_HTML_Archive.zip` をダウンロードして展開し、`npm run convert` を再実行するだけ。outputディレクトリは毎回の実行で完全に再生成される。

## ドキュメントの翻訳に貢献できるか？

できる。[CONTRIBUTING.md](https://github.com/yuis-ice/rtx-manual-to-md/blob/master/CONTRIBUTING.md) を参照。`docs/` 以下に追加の言語ディレクトリを作るプルリクエストは歓迎する。
